Application Overview

Adaptive Execution Planner is a goal-to-execution planning tool. It is cleanly separated into four architectural tiers:

  • UI & Components (src/components/): Lightweight React components handling presentation, user events, and local visual states.
  • Application State & Reducer (src/context/PlannerContext.tsx): React Context managing state transitions, progress tracking, and immutable revision logging.
  • Persistence Layer (src/lib/storage.ts): SSR-safe, schema-validated browser storage using localStorage.
  • Pure Scheduling Engine (src/lib/engine.ts): Standalone, zero-dependency mathematical engine implementing topological sorting, capacity allocation, multi-factor feasibility detection, and recovery proposal generation.

Architecture Reference Route

Follow this 3-stop route to understand how the codebase executes and preserves plan integrity:

Stop 1: UI Interaction & Preview Boundary

Location: src/components/ReplanReviewModal.tsx

This component renders the interactive Replan Review dialog. Notice that changing recovery options calls computeReplanPreview() and recalculates local state in-memory. Clicking "Cancel" simply closes the modal with zero mutations to the active plan.

Stop 2: Deterministic Scheduling & Diagnostic Math

Location: src/lib/engine.ts → computeReplanPreview(), allocateTasksToDays()

The pure engine takes the goal, incomplete tasks, and capacity. It evaluates prerequisite DAG ordering, performs daily capacity bin-packing, calculates multi-factor feasibility (flagging whether an issue is an aggregate hour deficit or a sequential bottleneck), and computes recovery options. It contains 0 side effects and 0 external dependencies.

Stop 3: State Commit & Audit Persistence

Location: src/context/PlannerContext.tsx → plannerReducer (APPLY_REVISION)

When the user clicks "Apply Revised Plan", this reducer action applies the revision, increments the plan version, records a new entry in revisionHistory, and immediately persists the updated state to localStorage via src/lib/storage.ts.

"To Change This, Start Here"

  • Add a new recovery proposal algorithm: Modify evaluateRecoveryOptions() in src/lib/engine.ts.
  • Modify task completion or blocked rules: Inspect src/components/TaskCard.tsx and TOGGLE_TASK in src/context/PlannerContext.tsx.
  • Customize the sample demonstration project: Edit SAMPLE_GOAL and SAMPLE_TASKS in src/lib/sampleData.ts.
  • Adjust storage keys or schema validation: Inspect validateStoredState() in src/lib/storage.ts.

A Practice to Reuse

Separate Algorithmic Math from Framework State:

By extracting the entire scheduling, topological sort, and feasibility engine into a standalone, pure TypeScript module (src/lib/engine.ts), the business logic became trivial to test. All 12 engine invariant tests in tests/engine.test.ts run in less than 50ms without mocking React, the DOM, or browser storage.
